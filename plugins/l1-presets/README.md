# 角色协作 · plan / work / code / review

选择 plan 后直接聊天、提问或交代任务即可。plan 会按需要读文件、搜索和调研；需要实施时，协调 work、code 和独立 review 完成任务，再把结果交给用户。

日常使用不需要先填写预算、启动轮次或单独批准方案。目标明确就继续执行；只有缺少关键资料、需要用户决定业务取舍或超出任务范围时才询问。原生工具的权限请求仍由 DSH 处理。

## 怎么协作

用户 ↔ plan → work → code → work → review → work → plan ↔ 用户。

- plan 直接回答简单问题，调查项目现状，把实施目标和验证要求交给 work。
- work 协调实施、运行检查、安排独立审核，并跟进修复。
- code 是任务中唯一的源码写入者，负责改动与必要验证。
- review 独立读取改动，报告通过范围、未覆盖项和阻断问题，不修改文件。

同一任务保持一个 work，并继续使用已有 code。首次派发返回的 subagentId 交给原生 send_message 的 agent_id 参数继续沟通，list_agents 用于查看状态；空闲子会话会收到新一轮消息，工作中的子会话会在后续步骤收到补充。每次正式审核及修复后的复审都新建 review。

派发和消息投递回执不代表任务完成。plan 和 work 需要等待真实回报，确认结果后再交付。旧执行尚未确认停止时不创建替身，也不启动第二个源码写入者。

## 工具范围

| 角色 | 文件工具 | 命令与其他工具 |
| --- | --- | --- |
| plan | 读、搜索、查看图片；无写入和编辑 | 网页、任务清单、必要提问、派发 work 和原生协作；无 shell |
| work | 读、搜索、查看图片；无写入和编辑 | 网页、shell、作业检查、派发 code/review 和原生协作 |
| code | 读写、编辑、搜索、查看图片 | shell、作业检查、网页、向 work 回报 |
| review | 读、搜索；无写入、编辑和图片工具 | 检查清单、向 work 回报；无 shell |

四个角色均加载项目说明、时间上下文、技能工具和标准上下文压缩。work 的 shell 用于验证；禁止它通过命令修改产品属于角色纪律，并不是文件系统隔离保证。单写入者与独立审核由角色工具配置和协作约定共同维持，L1 没有持久执行控制器。

## 显式受控任务

chain_* 工具属于另行选择的受控轮次，不是日常聊天或协作的前置步骤。用户明确要求这类任务时，应按 L2 协议记录目标、预算、证据和停止状态；已有受控会话及其子会话继续遵守原授权，不能切换角色或改用原生工具绕过限制。

本版只调整日常角色协作。受控轮次已发现的透明 provider 包装重复计量及本地拒绝后的上界记账问题没有在 L1 中修复。历史记录保留，其用量不能当作账单。L2 的覆盖与限制见 [验收说明](../l2-protocol/ACCEPTANCE.md)。

## 安装与验证边界

包版本为 1.1.0-workflow.1；四个 preset 的定义在 cordis.patch.yml，协作约定在 [ROUND-PROTOCOL.md](protocol/ROUND-PROTOCOL.md)。这里的 plan 是协作角色，本包没有挂载要求审批后才能实施的内置 plan-mode 插件。

使用独立版本副本安装并保留旧版供回退；安装和加载状态以实际部署回执为准。修改源码不代表已加载，YAML 或工具配置检查也不代表真实模型已完成协作。安装后应在新建的 plan 会话中检查当前角色与工具，已存在会话可能保留旧配置。
